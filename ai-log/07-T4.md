  1. Run path: keep the web service, with fixes

  The reviewer's run is a dev run anyway, since production infra is out of
  scope. The README in T6 should say it's a dev server. This also needs no
  backend change and no CORS (T3 left that open).

  - node_modules trap. Compose reuses an anonymous volume when it recreates a
    container. After a package.json change, --build produces a new image, but
    the old node_modules still shadows it. Install with npm ci in the image,
    bind-mount ./frontend:/app, add the anonymous /app/node_modules volume, and
    run make up with up -V (--renew-anon-volumes). -V doesn't touch pgdata. Add
    a .dockerignore and a .gitignore for node_modules. The lockfile has to be
    generated in a container, because there's no host node.
  - --no-deps for checks. docker compose run starts depends_on services. web
    should depend on api healthy, so the frontend make check steps need run --rm
    --no-deps web …. Otherwise every check boots api and db.
  - Vite config. server.host: 0.0.0.0, the proxy target from an env var
    (http://api:8000), and the port mapped as 127.0.0.1:5173:5173. If HMR is
    silent on the bind mount, fall back to usePolling.
  - Healthcheck. make up --wait is happy with a service that has no healthcheck,
    but a cheap one on web makes failures visible.
  - Compose and docs. docker-compose.yml changes, but nothing under backend/.
    CLAUDE.md's Commands and Stack sections would also need updating, and that's
    your file, so you decide.
